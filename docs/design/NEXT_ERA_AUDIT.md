## Architecture And Route Reality

`App.tsx` mounts font loading, theme, i18n, Firebase/auth, React Query, snackbars, user safety, activity and AI providers. `RootNavigator` coexists with `YouthGate`, `LegalGate` and purchases identity sync. An initial font loader and session-bootstrap overlay are user-facing states, not extra stack routes.

- Signed out or pending role selection: `Auth`; the latter is reset to `RoleSelection`.
- Authenticated guest: **PlayerApp**, not the legacy public discovery guest shell. Public deep links can remain in `GuestApp/PublicPortfolio` or `GuestApp/PlayerDetail`.
- Player: `PlayerApp`; scout and coach: `ScoutApp`. Coach has embedded roster/observations, not a separate navigator. Staff moderation is embedded and claim-conditioned, not an Admin tab.
- Player tabs: `Home`, `Performance`, `Media`, `Discover`. Discover is omitted in private mode. Performance segments are development/stats/career; Media segments are library/reels/GPS.
- Scout tabs: `Dashboard`, `Discover`, `Pipeline`, `Trials`. Trials contains trials/reports segments.
- Shared public Passport is available from player, scout and guest stacks. Preview mode must remain visibly different from an actual public read.
- Player `GlobalSearch` renders **FootballMemoryScreen**, using `useFootballMemory`; scout `GlobalSearch` renders **GlobalSearchScreen**, using owned search records. They are different screens under the same route name.
- No standalone Settings tab, Statistics tab, Career tab, GPS route or Reports tab exists in the current tree. Do not invent these in walkthroughs.

Primary route evidence: `src/navigation/types.ts`, `RootNavigator.tsx`, `AuthStackNavigator.tsx`, `PlayerRootNavigator.tsx`, `PlayerTabNavigator.tsx`, `PlayerPerformanceTab.tsx`, `PlayerMediaTab.tsx`, `PlayerDiscoverTab.tsx`, `ScoutRootNavigator.tsx`, `ScoutTabNavigator.tsx`, `ScoutTrialsTab.tsx`, `GuestRootNavigator.tsx`.

- Screen: safe-area edges, tab embedding, custom header/actions/footer, refresh, loading/error/retry/empty and automatic network-offline notice. Offline notice is **informational**, not evidence that every mutation is durably queued.
- AppSafeAreaView, Section, CollapsibleSection, RevealSection, PreviewList; custom safe-area roots still need independent review.
- Button, Input, Text, Heading, Card, Badge, Avatar, StatCard, ChoiceChip, CheckboxRow, Dropdown, SearchBar, progress and rating primitives.
- Modal supports keyboard avoidance, safe-area fullscreen/sheet variants, close controls, SnackbarHost and reduced motion. BottomSheet is a separate implementation with different sizing/keyboard/inset behavior. Neither source inspection establishes web focus trap, VoiceOver isolation or return-focus correctness.
- AppTabBar, NavigationTabBar adapter, HeaderIconButton/cluster and TabSegmentControl; safe areas, selected semantics and unread badges remain central regression targets.
- SkeletonLoader, EmptyState, LoadingScreen, Snackbar; evidence primitives ProvenanceBadge, EvidenceStateBadge, FreshnessLabel and EvidenceCard already encode trust distinctions.
- FlashListView exists for discovery. Other ScrollView/map-based lists are not automatically virtualized by redesigning cards.

Missing or inconsistent patterns to standardize: recoverable error action versus exit action; stale/offline/draft distinctions; source-deleted/private/expired evidence; compact secondary headers; consistent modal action rows; non-color provenance/status; accessible chart summaries; long-form consent/error announcements; deterministic sanitized capture fixtures and per-asset provenance.

## Visual, Accessibility And Marketing Findings

1. **High: completeness cannot be inferred from flagship screenshots.** CareerReplay, FootballMemory/global search, GPS, privacy/settings/plan, requests/player trials, overlay gates and all editors contain local layouts. Shared token propagation is not an individually redesigned-and-tested screen. Track these as remaining secondary work until reviewed.
2. **High: shell state coverage differs.** Discovery and pipeline use custom roots; YouthGate/LegalGate use absolute overlays; BottomSheet differs from Modal. Common offline banners, insets, keyboard and error handling do not propagate uniformly. Test state transitions and retained content, not only happy paths.
3. **High: claims are capability-gated.** Video readiness explicitly lists continuous tracking, event detection, pitch mapping, physical metrics and video statistics as unavailable, with real-footage accuracy unvalidated. Keep absent metrics unknown, possible events needing review, and consent/provider gates fail-closed. Generated campaign photography must not be presented as a real player endorsement or captured gameplay.
4. **Medium: source-level theme escapes remain.** CareerReplay has literal dark gradient/text colors; result rows, editor fields, chart internals and per-feature sections use local geometry. Review light/dark contrast and export surfaces independently. A grep hit is a review target, not a measured contrast violation.
5. **Medium: retry semantics can be misleading.** AnalysisReport uses back navigation for Screen's retry callback. Scout report/trial inboxes expose errors without matching explicit retry in inspected screen usage. Player trials does not show equivalent screen-level load-error handling. These are observed integration risks, not proof of a failed backend request.
6. **Medium: localization is not just key parity.** `usePublicPortfolio` contains English fallback strings. Result metadata, generated legal body language, dates/numbers, long German labels and user-entered content need separate review. Seven locale directories must remain intact; auth alert improvements observed during parallel work are not a full locale/accessibility certification.
7. **Medium: evidence charts and rating systems need explainability.** Radar/comparison/heatmap/trend output must have textual values, source/sample/time context and unknown treatment. Status/progress/selection must not rely on green/gold alone. Distinguish self-report, endorsement and automated inference everywhere, including exported assets.
8. **Medium: form/overlay accessibility is unproven.** Verify minimum touch targets, Dynamic Type, readable validation, keyboard reachability, modal isolation and focus restoration for every editor. Shared screen-reader labels are a useful baseline; real VoiceOver/keyboard checks remain open.
