# B-26 full-claims exports and offline mixed-plan comparison

Implemented tooling, not a live validation result. Export is disabled by default. No API request can enable it,
choose a destination or obtain the claims. This code changes the instrumented worker configuration; establish
instrumentation parity against the historical CPU8 anchor before treating newly collected A as that reference.
The historical present-only rounded claims cannot be upgraded by padding, interpolation or guessed abstentions.
B-26 remains open, including real task/lease/capacity checks and final-attempt reconciliation.

## Private collector

Only in a separately authorized validation environment, set server configuration:

- `SCOUTX_B26_EXPORT_ENABLED=true` (exact value after whitespace trimming).
- `SCOUTX_B26_CONTEXT_ROOT`: absolute private directory containing `<jobId>.json`.
- `SCOUTX_B26_EXPORT_ROOT`: absolute private output directory, outside publicly served paths.

Provision owner-only directory ACLs, access control, storage durability, retention and capacity on the host.
Directory mode 0700 is requested; it does not configure Windows ACLs or a cloud bucket. Keep exports and contexts
out of source control. The collector runs before the temporary timeline disappears. A configured but missing,
incompatible or corrupt context fails closed; it does not silently fall back to an unrecorded evaluation.
Disabling export preserves the normal endpoint. No export destination or new claims field enters its response.

Context JSON must contain `metadata`, `segmentPlan`, `schedule` (`sequential` or `orchestrated`) and
`checkpointSourceSha256`. Hashes below are lowercase SHA-256. Compute canonical object hashes using
`scoutx_tracker.b26_export.digest` (sorted compact UTF-8 JSON, finite numbers); file hashes use `file_digest`.

Required `metadata` sections:

- `input`: `videoStreamSha256`, `sampleTimesSha256`, `sampledFrames`, `durationSec`, `width`, `height`, `fps`,
  `pixFmt`, `colorTransfer`. Hash the complete ordered sampling timestamp list; do not round it.
- `target`: exact parsed `ResolveRequest.target.model_dump()` including defaults.
- `engine`: `sourceSha256` (frozen source artifact hash), `lockSha256`, `imageDigest` (`sha256:...`), `version`,
  `models` (nonempty model-name-to-file-hash mapping).
- `settings`: nonempty `stage1`, `resolve`, `decoder` objects. Stage1 must match checkpoint settings exactly.
  Include all effective flags, thresholds, precision and decoder/color choices, not just nondefault settings.
- `groundTruth`: `sha256` of label file bytes, `timeBasis` (`unshifted` or corrections-file SHA-256), integer
  `width` and `height` of the labelled image coordinate system.
- `artifacts`: `discoverySha256` of the merged effective sightings list, `feedbackSha256` of the exact parsed
  feedback model dump and `auxiliaryCacheSha256` of a relative-path-to-file-hash mapping of all stage1 JSON files
  whose filename contains `cache` (case insensitive). Empty list/object hashes are valid; missing hashes are not.
- `resources`: positive `cpu`, `memoryGiB`, nonempty `effectiveProviders` list and `threads` object. Record actual
  thread settings and effective sessions. Include consent/version/feedback revision and any further frozen controls
  as metadata extensions. Every extension is compared too; unknown differences are not ignored.

`segmentPlan` is an ordered list of `{index, startSec, endSec}`: zero-based indices, contiguous half-open bounds
from zero to exact duration, 1–61 chunks, each at most 900 seconds. Obtain bounds from the planner, not a uniform
chunk-size approximation. The checkpoint source hash is the service's job/URL-derived checkpoint identity, **not**
the stream hash. Different job namespaces can therefore have different checkpoint identities.

Before analysis, the hook checks target/feedback binding, effective discovery and known JSON caches. After
analysis it verifies report invariants, each checkpoint's input/settings and detections/meta file hashes, actual
bounds and full sample grid against the timeline. It checks array shapes, finite boxes/times, unique increasing
timestamps, all states and present flags. Absent rows have null boxes, never stale coordinates. It copies no media,
embeddings, other-player identities or raw report. It writes a unique attempt directory atomically, with record
last; failures remove only that attempt's staging directory. Repeated resolves retain distinct exports.

Image/source/model hashes, decoded stream identity, effective resolve/decoder flags and resource allocation are
**operator/server-attested context**, not runtime measurements or signatures. Review their provenance independently.
Known JSON-cache inventory does not prove that an external or unlisted cache was empty. Context must describe such
inputs explicitly. Byte hashes detect accidental alteration, not a malicious writer able to replace the context
and records together. Do not claim this collector cryptographically proves the execution environment.

Each attempt contains:

- `full_claims.json`, schema `pitchproof.b26.full-claims.v1`, `frames`: exact `[time, state, box-or-null, present]`
  for **every** sampled timestamp, including abstentions. No timestamp or box rounding and no resampling.
- `record.json`, schema `pitchproof.b26.resolve-export.v1`: complete status, frozen metadata, explicit plan and
  hash, schedule, context hash, checkpoint source identity, claims filename/byte hash/count and a report-summary
  hash over schema, target, coverage, identity, invariants and analysedRange. The summary hash is not a raw-report
  export. Collect raw reports and task traces separately through the runbook's private evidence process.

## Offline comparator

From `workers/football-cv`, using the worker Python environment:

```powershell
python bench/compare_b26.py --a PRIVATE/A/record.json --b PRIVATE/B/record.json --c PRIVATE/C/record.json --ground-truth PRIVATE/labels.json --reference-sha256 FROZEN_A_RECORD_SHA256 --out PRIVATE/comparison.json
```

Supply `--corrections PRIVATE/corrections.json` only when all contexts freeze that corrections file hash.
Freeze A's record hash before inspecting candidate outputs. Never regenerate the reference hash to excuse drift.
This command does no decoding, inference, network work or cloud operations. Choose the correct completed attempt
explicitly; it does not select the latest retry automatically. Preserve attempt-to-task/publication correspondence
in private traces. A completed resolve export alone does not prove that its report won publication fencing.

A→B permits explicit layout changes only; B→C permits schedule changes only; A→C permits both. All frozen metadata
must match exactly, including types and extensions. Labels, corrections, sidecar hashes, full sample grid, plans,
coverage and frame counts must validate first. Legacy records and the API's 2 Hz strip are rejected. Accuracy is
recomputed from full claims with the existing scorer and explicit coordinate dimensions; stored accuracy is not
trusted. The fixed repository `balanced_5.2.json` gate applies to absolute accuracy, relative accuracy and full
state/box agreement. Baselines must have correctly claimed labelled target evidence. Direct A→C gating prevents
small accepted pairwise changes accumulating into an unacceptable end result. Scorer tolerances/rounding remain
unchanged; this tooling does not extend the interval gate into proof of whole-match identity.

Exit codes: **0** all comparisons pass, **3** accuracy/agreement failure, **5** invalid/noncomparable input,
**7** missing input. The result JSON records gate/labels/reference/candidate/plan hashes and individual comparisons.
`compare_runs.py` and its same-layout `chunkSec` rules are unchanged.

Synthetic regression tests cover exporter/checkpoint integrity, full/absent sampling, target/context checks,
endpoint cleanup/privacy, atomic writes, mixed plans, frozen inputs, corruption, wrong-player accuracy and cumulative
drift. They establish tooling behavior only. Real instrumentation parity, accuracy, retry/lease behavior, supported
capacity and rollback remain unexecuted requirements in the [runbook](../../../docs/release/b26-integration-capacity-runbook-2026-11-23.md).
